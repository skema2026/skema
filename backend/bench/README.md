# 결과보고서용 측정 (bench)

결과보고서 6장의 수치를 낸 스크립트입니다. 자동 테스트(`tests/`)와 달리 수치를 재는 용도라 pytest에 들어가지 않습니다.
모두 운영 코드(`app/`)를 그대로 불러 씁니다. 결과는 `results/`에 있습니다 (2026-11-13, main `51db48b`).

| 측정 | 스크립트 | 결과 파일 |
| --- | --- | --- |
| 공부 블록 배치·다시 짜기 알고리즘 | `algo_sim.py`, `mutants.py` | `results/algo_result.json` |
| 서버 부하 | `load/` (Locust) | `results/load_summary.json` |
| 시간표 인식률 (방식별 비교) | `ocr/bench_ocr.py` | `results/ocr_dev14_summary.json` |

## 1. 알고리즘 (`algo_sim.py`)

무작위 대학생 시간표를 만들어 `free_slot_starts`·`plan_study_blocks`·`plan_moves`에 넣고, 결과가 규칙을 어기는지 검사합니다. DB·서버 없이 돌고, 같은 시드면 같은 결과가 나옵니다.

- 시간표: 요일마다 수업 0~4개(50·75·90·100·150·180분), 저녁 아르바이트·운동, 자정을 넘겨 자는 수면 시간, 시험 1~4개, 온보딩 설정(며칠 전부터·주 며칠·하루 몇 시간) 무작위
- 규칙 18개 + 결정성: 30분 칸, 수업·개인 일정·시험과 안 겹침, 수면 시간 제외, 블록끼리 안 겹침, 오늘~시험 전날, 설정 준수, 오늘은 지금 이후, 저녁→오후→오전 순서 / (다시 짜기) 대상만 옮김, 마감 안, 블록 길이 유지, 자리가 있으면 '자리 부족'이라 하지 않음 / 같은 입력이면 같은 결과
- `mutants.py`: 계산 함수에 일부러 버그 7종을 넣고 돌려서, 검사기가 버그마다 위반을 잡아내는지 확인합니다

```bash
cd backend
python bench/algo_sim.py --n 10000 --seed 20261113 --out bench/results/algo_result.json   # 약 10초
python bench/mutants.py
```

**결과 (1만 개)**: 규칙 위반 0건 (공부 블록 160,510개, 다시 짜기 대상 26,228개), 결정성 1만 건 모두 같음, 목표 공부 시간 98.3% 배치, 저녁(19시 이후) 79.2%, 다시 짜기로 옮긴 비율 93.7%(시험이 이미 지난 블록 제외), 계산 시간 중간값 배치 0.11ms·다시 짜기 0.02ms. 버그 7종은 모두 잡힘.

## 2. 서버 부하 (`load/`)

운영과 같은 코드·구성(uvicorn 프로세스 1개, DB 연결 최대 30개, MySQL 8.0)을 로컬에 띄우고 서버를 CPU 1코어에 고정해 Locust로 잽니다. **로컬 서버에만 씁니다** (`locustfile.py`가 다른 주소를 거부).

가상 사용자는 3~8초 간격으로 대시보드 열기(요청 6개) : 완료 체크 : 다시 짜기 미리보기 : 공부 블록 다시 배치 = 10 : 3 : 2 : 1 로 움직입니다. 로그인은 따로 잽니다(실제 사용자는 한 번 로그인하면 24시간 토큰을 씀).

```bash
cd backend && pip install -r bench/load/requirements.txt
# 1) MySQL 8 + 서버 (CPU 0번)
DATABASE_URL=mysql+pymysql://<user>:<pw>@127.0.0.1:3306/<db> SECRET_KEY=<로컬용 값> alembic upgrade head
DATABASE_URL=... SECRET_KEY=... taskset -c 0 uvicorn app.main:app --port 8100
# 2) 가짜 학생 300명 → 토큰 → 단계별 측정 → 요약
cd bench/load
python seed.py --host http://127.0.0.1:8100 --n 300
python tokens.py http://127.0.0.1:8100
OUT=run sh run_load.sh        # 약 12분
python summarize_load.py run
```

**결과**

| 동시 사용자 | 초당 요청 | 응답 중간값 | 상위 5% | 오류율 |
| --- | --- | --- | --- | --- |
| 50명 | 42 | 5ms | 81ms | 0% |
| 100명 | 85 | 5ms | 74ms | 0% |
| 200명 | 162 | 6ms | 100ms | 0% |
| 300명 | 235 | 12ms | 160ms | 0.02% |
| 500명 | 처리 한계 초과 | 100ms | 310ms | 2.85% |

- 쉬지 않고 요청하면 최대 초당 약 360건 (상위 5% 47ms)
- 로그인은 비밀번호 확인(bcrypt) 때문에 1코어당 초당 약 3번
- 500명부터 DB 연결 30개가 모두 차서 요청이 30초 기다리다 실패했고, 부하가 끝난 뒤에도 쌓인 요청을 처리하느라 약 10분 뒤에 정상으로 돌아왔습니다
- 오류율에서 같은 계정을 여러 가상 사용자가 나눠 쓰다 생긴 404(다른 가상 사용자가 다시 배치해서 지워진 블록을 누름)는 뺐습니다. `load_summary.json`의 `fail_rate`에는 들어 있습니다
- 로컬 1코어 기준입니다. 운영(Railway 싱가포르)에서는 요청마다 네트워크 시간이 더해집니다

## 3. 시간표 인식률 (`ocr/bench_ocr.py`)

같은 캡처·같은 정답으로 네 가지 방식을 비교합니다. 블록 위치는 모두 같은 OpenCV 단계를 쓰고 글자 읽는 방법만 다릅니다.

| 방식 | 설명 |
| --- | --- |
| P0 위치만 | OpenCV 격자·블록 찾기만 (요일·시간만, 과목명 없음) |
| P1 범용 OCR 그대로 | 블록 그림을 Tesseract에 그대로 |
| P2 전처리 + Tesseract | 흰 글씨 반전·줄 나누기·크기 맞추기 후 Tesseract, 보정 규칙은 끔 |
| P3 SKEMA 전체 | 운영 코드 그대로 (전처리 + 과목명 사전·영어 약어 다시 읽기·같은 수업 맞추기) |

캡처와 정답은 남의 시간표라 저장소에 올리지 않습니다. `<세트폴더>/img/`에 캡처, `<세트폴더>/truth.py`에 정답(`ocr/truth_template.py` 양식)을 두고 돌립니다.

```bash
cd backend
ETA_TESSDATA_DIR=/opt/tessdata OMP_THREAD_LIMIT=1 python bench/ocr/bench_ocr.py <세트폴더> --out result.json -v
```
